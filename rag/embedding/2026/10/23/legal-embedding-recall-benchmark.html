한국어 판례 검색을 위한 임베딩 모델의 Recall과 nDCG 비교

BGE-M3, KURE-v1, Multilingual E5 Large의 문서 단위 검색 성능 평가

Oct 23, 2026 About 12 mins

#RAG#Embedding#Recall#nDCG#Benchmark#BGE-M3#KURE-v1#E5#법률검색

초록

법률 RAG의 검색 모델을 선택하기 위해 한국어 판례 데이터에서 세 임베딩 모델의 관련 문서 회수 성능과 순위 품질을 비교하였다. EVE-Bench-Legal-2.0의 판례 59,786개와 고유 질의 5,998개를 사용하고, BGE-M3, KURE-v1, Multilingual E5 Large로 각 판례를 하나의 벡터로 표현하였다. 모든 질의에 대해 전체 문서와 코사인 유사도를 계산한 뒤, 동일한 검색 결과에서 Recall@K와 이진 nDCG@K를 질의별로 구하여 평균하였다.

그림 1. 모델별 평균 Recall@20(왼쪽, %)과 이진 nDCG@10(오른쪽, 0~1)

KURE-v1은 평가한 모든 K에서 Recall과 이진 nDCG가 가장 높았다. 그림 1은 관련 문서 회수와 상위 순위 품질을 각각 비교한 결과다. 이에 따라 이번 문서 단위 판례 검색의 기본 임베딩 모델로 KURE-v1을 선택하였다. 다만 모델별 입력 길이가 다르고 단일 데이터셋에서 평가하였으므로, 결과의 적용 범위는 본 실험 조건으로 한정한다.

주제어: 법률 RAG, 한국어 판례 검색, 임베딩 모델, Recall@K, 이진 nDCG@K

1. 서론

법률 RAG는 검색한 판례를 근거로 답변을 생성한다. 따라서 생성 모델을 비교하기에 앞서, 검색 단계에서 관련 판례를 어느 정도 확보할 수 있는지 확인할 필요가 있다. 모델의 공개 성능이나 한국어 지원 여부만으로는 실제 법률 데이터에서의 선택 근거를 충분히 마련하기 어렵다.

본 실험의 목적은 한국어 판례 검색에 사용할 임베딩 모델의 기준선을 확보하는 데 있다. 로컬 Mac mini M2·16GB 메모리 환경의 자원 제약을 고려하여, 약 5.6억 파라미터 규모로 로컬에서 실행 가능한 BGE-M3, KURE-v1, Multilingual E5 Large를 비교 대상으로 선정하였다. 최신 한국어 검색 상위 세 모델을 포괄하는 비교는 아니며, 해당 환경에서 실행 가능한 후보 간 성능을 평가하였다. 검색엔진의 근사 탐색 설정이 결과에 개입하지 않도록 전체 문서에 대한 정확 검색을 수행하고, 관련 판례의 회수율은 Recall@K로, 순위 품질은 이진 nDCG@K로 비교하였다.

연구 질문은 두 가지다. 첫째, 동일한 판례 집합에서 어느 모델이 더 많은 관련 문서를 회수하는가. 둘째, 관련 판례를 상위에 배치하는 순위 품질은 어떠한가. 검색 결과 수 K에 따른 두 지표의 변화도 함께 살펴본다. 이 결과를 바탕으로 기본 모델을 선택하되, 생성 답변의 정확도나 서비스 응답 속도까지 검증한 것으로 해석하지 않는다.

2. 실험 방법

2.1. 데이터와 정답 구성

평가에는 EVE-Bench-Legal-2.0의 문서 집합과 관련성 판정인 Qrels를 사용하였다. 검색 대상은 판례 59,786개 전체이며, 관련성 등급이 0보다 큰 문서를 해당 질의의 관련 문서로 정의하였다. 질의당 관련 문서 수는 평균 약 7.20개였다.

원본 Qrels 5,999행 중 동일한 질의가 두 번 등장하는 사례가 있었다. 해당 질의의 관련 문서 집합을 합치고, 같은 문서에 대한 등급은 최댓값을 유지하였다. 이 병합 정책을 적용한 고유 질의는 5,998개였으며, 평가에서 제외한 질의는 없었다. 중복 질의를 마지막 행으로 덮어쓰는 처리와는 정답 집합이 달라질 수 있으므로 결과를 재현할 때 같은 정책을 적용해야 한다.

2.2. 문서 표현과 모델 설정

각 판례의 제목과 본문을 줄바꿈으로 연결하여 입력하였다. 문서를 청크로 나누지 않고, 판례 하나를 벡터 하나로 표현하는 조건을 유지하였다. 모델에 전달하는 원문은 동일하게 구성하되, 접두어와 최대 입력 길이는 각 모델의 입력 규칙을 적용하였다.

표 1. 비교 모델과 입력 설정

2.3. 검색과 평가 지표

각 질의를 59,786개 전체 문서와 비교하여 유사도가 높은 순서로 100개를 추출하였다. 정답으로 판정된 후보만 검색하는 제한은 두지 않았다. 근사 최근접 이웃 검색, 키워드 검색, 재순위화는 적용하지 않았다.

질의 q의 관련 문서 집합을 G(q), 상위 K개 검색 결과를 Sₖ(q)라고 하면 Recall@K는 다음과 같다.

**Recall@K(q) = Sₖ(q) ∩ G(q) / G(q) **

최종 점수는 전체 5,998개 질의의 Recall@K를 산술평균한 값이다. 예를 들어 관련 판례가 5개인 질의에서 상위 10개 결과에 관련 판례 3개가 포함되면 Recall@10은 60%이다. 이처럼 질의별 점수를 먼저 구한 뒤 평균하여 각 질의에 같은 가중치를 부여하였다.

Recall은 관련 판례를 얼마나 회수했는지, nDCG는 관련 판례가 얼마나 앞에 배치되었는지를 평가한다. 두 지표는 동일한 검색 결과로 계산하며 별도의 모델 추론을 요구하지 않는다.

이번 nDCG는 Qrels의 양수 등급을 모두 1로 변환한 이진 nDCG다. 관련성 등급 1과 2의 차이는 반영하지 않으며, 관련 문서와 비관련 문서의 순서만 평가한다. 따라서 ‘더 중요한 판례를 앞에 놓는 능력’을 직접 검증했다고 해석하지 않는다.

질의별 이진 nDCG는 상위 K개에서 관련 문서가 등장한 순위 i에 1 / log₂(i + 1)의 가중치를 더한 DCG를, 관련 문서를 모두 앞에 배치한 이상적 순서의 DCG인 IDCG로 나눈 값이다. 최종 점수는 질의별 DCG@K / IDCG@K의 산술평균이다. 값의 범위는 0~1이며, 백분율이나 답변 정확도가 아니다.

평가한 K는 1, 5, 10, 20, 50, 100이다. Recall은 실행 시 MTEB 2.26.11과 교차 검증하였다. nDCG도 같은 실행의 MTEB 원본에 저장되어 있었으며, 이번 문서 개정에서 질의별 평균과 검색 순위 기반 독립 재계산으로 검증하였다. 모델 추론과 검색은 다시 실행하지 않았다.

2.4. 실행 환경과 재현 조건

전체 평가는 2026년 10월 20일 로컬 macOS 15.5의 Apple MPS 장치에서 수행하였다. 추론 자료형은 torch.float32, 배치 크기는 4였으며, Python 3.12.10, PyTorch 2.14.1, SentenceTransformers 5.7.0을 사용하였다. 모델 파일을 내려받은 뒤 임베딩 연산은 로컬에서 실행하였다.

데이터와 모델의 리비전을 고정하고, 입력 설정과 실행 환경을 결과 메타데이터에 저장하였다. 데이터셋 리비전은 1580448204d13ec8af13745086ffa91cfda407c3이다. 모델 리비전과 실행 절차는 벤치마크 구현 및 설정에서 확인할 수 있다.

K를 늘리면 세 모델 모두 회수율이 높아졌다. 이는 기본 모델 선택과 별개로 후보 문서 수가 관련 판례 확보에 큰 영향을 준다는 것을 보여준다. 다만 상위 100개 검색 결과를 모두 생성 모델에 전달하는 구성이 적절한지는 본 실험에서 평가하지 않았다.

nDCG는 K에 따라 평가 구간과 이상적인 순서의 분모가 함께 달라진다. 따라서 Recall처럼 K가 커질수록 반드시 증가하지 않는다. 특히 K=1의 높은 점수와 K=10의 낮은 점수만으로 검색 품질이 악화되었다고 해석할 수 없으며, 모델 비교는 동일한 K에서 수행한다.

3.3. 첫 번째 검색 결과와 전체 정답 회수

Recall@1은 첫 결과가 관련 문서인 질의의 비율과 구분해야 한다. 관련 판례가 10개인 질의에서는 첫 결과가 관련 판례여도 Recall@1이 10%에 그친다. 따라서 KURE-v1의 Recall@1 18.36%를 첫 검색 결과의 적중률로 해석할 수 없다.

저장된 순위에서 첫 결과의 적중 여부를 별도로 계산하였다. 표 4는 첫 결과가 관련 판례인 비율과, 상위 후보 전체에서 관련 판례를 놓친 질의 수를 비교한다.

4. 고찰

4.1. 모델 선택에 대한 시사점

이번 조건에서는 KURE-v1을 기본 모델로 채택할 근거가 가장 명확하였다. 모든 K에서 가장 높은 Recall과 이진 nDCG를 보였고, 문서 입력도 잘리지 않았다. 그림 1의 요약 비교와 두 지표의 전체 곡선은 이 선택을 일관되게 뒷받침한다. 다만 이 차이에 대한 통계적 유의성 검정은 수행하지 않았다.

BGE-M3는 후속 검색 실험의 비교 기준으로 유지할 수 있다. Multilingual E5 Large는 이번 문서 단위 평가에서 상대적으로 낮은 Recall과 이진 nDCG를 보였으나, 이 결과만으로 청크 단위 검색에서도 같은 순위가 유지된다고 볼 수는 없다. 문서 잘림이 점수에 영향을 주었을 가능성은 있으나, 길이를 통제한 별도 실험이 없으므로 성능 차이의 원인을 잘림으로 단정하지 않는다.

4.2. 평가의 한계

본 평가는 단일 판례 데이터셋과 한 번의 전체 실행에 근거한다. 다른 법률 문서 유형이나 실제 서비스 질의로 결과를 일반화하려면 추가 검증이 필요하다. 또한 후보 풀에 기반한 Qrels는 전체 문서의 관련성을 완전하게 판정한 정답 집합으로 볼 수 없으므로, 결과는 제공된 관련성 판정에 대한 회수율과 순위 품질로 해석해야 한다.

검색 정확도와 최종 답변 품질도 구분해야 한다. 본 실험은 생성 답변의 정확성, 인용의 적절성, 재순위화 효과를 측정하지 않았다. 따라서 높은 Recall이 곧바로 더 정확한 법률 답변을 보장하지는 않는다. 후속 실험에서는 동일한 평가 기준을 유지하면서 청킹, Hybrid Search, Reranker가 후보 회수율과 최종 답변에 미치는 영향을 각각 확인할 수 있다.

5. 결론

판례 59,786개와 질의 5,998개를 대상으로 세 임베딩 모델을 비교한 결과, KURE-v1이 모든 K에서 Recall과 이진 nDCG 모두 가장 높은 점수를 기록하였다. 후보 수가 달라져도 모델 간 성능 순위가 유지되었으며, 입력 길이 제한으로 잘린 문서는 없었다. 이에 따라 한국어 판례를 문서 단위로 검색하는 본 프로젝트의 기본 모델로 KURE-v1을 선택하였다.

이 선택의 근거는 본 데이터와 검색 조건에서 관측한 회수율과 이진 관련성 기준의 순위 품질이다. 청킹 방식이나 검색 구조가 바뀌면 동일한 평가를 다시 수행해야 하며, 이번 결과는 그 변화량을 비교하기 위한 기준선으로 사용한다.

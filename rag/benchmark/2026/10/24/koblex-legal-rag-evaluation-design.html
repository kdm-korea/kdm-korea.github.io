KoBLEX 기반 법률 검색 테스트셋 생성

질문의 정답 근거를 법령에 매핑하고 개발용·최종 평가용 데이터로 나누기

Oct 24, 2026 About 7 mins

#RAG#KoBLEX#법률검색#테스트셋#데이터매핑

법률 RAG(Retrieval-Augmented Generation, 검색 증강 생성)의 검색 성능을 테스트하려면 질문마다 어떤 법령을 찾아야 하는지 정해져 있어야 한다. 이번에는 공개 벤치마크인 KoBLEX의 질문별 근거를 법령 코퍼스에 매핑하고, 정답표가 연결된 테스트셋을 생성했다.

평가 가능한 222문항을 개발용 dev 44문항과 최종 평가용 test 178문항으로 나눴다. 이 글은 원본 데이터에서 근거를 연결하고 두 분할을 생성하는 과정을 다룬다.

1. 원본 데이터와 연결의 문제

KoBLEX는 한국어 법률 질문에 대해 여러 법조문을 연결하는 추론을 평가하기 위한 벤치마크다. 공식 저장소에 따르면 사건 시나리오 기반 질문·답변 226개와 이를 뒷받침하는 법조문을 포함하며, LLM 기반 생성과 전문가 수정을 결합해 구축했다. 한국어 법령 코퍼스도 별도로 제공한다. KoBLEX 공식 저장소

사용한 원본은 질문·답변·근거 데이터인 JihyungL/KoBLEX-koblex와 법령 코퍼스인 JihyungL/KoBLEX-statute다. 질문 226개와 법령 233,544행을 사용했다.

  • QA(질문·답변 데이터): 질문 ID인 id, 사건 배경 background, 질문 question, 참고 답변 answer, 정답 근거 목록 contexts로 구성된다.
  • 법령 코퍼스: 법령·조문을 나타내는 index, 조·항·호 위치인 hierarchy, 해당 본문인 content로 구성된다. QA의 각 근거에도 이 세 필드가 있다.

검색 입력에는 배경과 질문만 사용한다. 참고 답변과 정답 근거는 평가용으로 보관한다.

두 원본에는 공통 고유 ID가 없다. index는 여러 항·호에서 반복되고, 같은 hierarchy에 서로 다른 본문이 있기도 하다. 근거 하나가 여러 법령 항목을 합친 본문인 경우도 있어, 필드 하나로 조인하는 대신 실제 본문을 검증해야 했다.

2. 근거와 법령의 매핑 기준

먼저 index, hierarchy, content가 모두 같은 법령 행만 병합했다. 원본 행 위치를 보존하면서 209,564개 항목으로 정리하고 각각 unit_id를 부여했다.

QA의 contexts는 근거별로 펼쳐 다음 순서로 매핑했다.

  1. 같은 index의 후보에서 제목·구조 항목을 제외하고, 계층과 전체 본문이 일치하는 항목이 하나면 연결한다.
  2. 단일 항목으로 연결되지 않으면 같은 조문의 본문 항목들을 원본 순서로 합쳐 비교한다. 근거의 계층과 같은 본문 항목이 존재하고, 각 하위 계층의 후보가 하나일 때만 허용한다.
  3. 그래도 일치하지 않으면 QA 근거의 등장 순서로 합쳐 비교한다.
  4. 전체 본문이 다르거나 후보가 모호하면 미해결로 남긴다.

비교에는 연속된 공백만 정리하고 숫자·구두점·개정 표기는 유지했다. 매핑 장부는 각 근거의 연결 대상과 판정 이유를 기록한 파일이다. 이 규칙으로 직접 생성했으며, LLM 추론이나 공식 매핑 파일을 사용하지 않았다.

3. 실제 데이터의 매핑 과정

qa_19_1hop_28은 상품 운송 지연으로 발생한 손해배상을 언제까지 청구할 수 있는지 묻는 질문이다. 아래는 이 질문과 첫 번째 근거에서 필요한 필드만 발췌한 예시다. 배경은 요약했고 본문의 …는 표시를 위한 생략이다. 실제 매핑은 생략 없는 전체 본문으로 비교했다.

{
  "id": "qa_19_1hop_28",
  "background": "상품이 늦게 도착해 손해가 발생했고, 인도 후 청구 가능 기간을 묻는 상황 [요약]",
  "question": "을은 갑에 대한 손해배상청구권을 어느 시점까지 행사할 수 있는가?",
  "contexts": [
    {
      "index": "상법 814조  운송인의 채권ㆍ채무의 소멸",
      "hierarchy": "상법 814조  운송인의 채권ㆍ채무의 소멸 1항",
      "content": "①운송인의 송하인 또는 수하인에 대한 채권 및 채무는 …"
    }
  ]
}

법령 코퍼스에는 같은 index를 가진 다음 네 행이 있다. 원본 행 번호는 0부터 시작한다.

원본 행 hierarchy의 위치 content 일부 판정
116390 제814조 제814조(운송인의 채권ㆍ채무의 소멸) 제목이므로 제외
116391 제814조 1항 ①운송인의 송하인 또는 수하인에 대한… 근거와 계층·전체 본문 일치
116392 제814조 2항 ②운송인이 인수한 운송을 다시 제3자에게… 다른 항
116393 제814조 3항 ③제2항의 경우에 있어서 재판상 청구를… 다른 항

index만 보면 네 행이 모두 후보지만, 계층과 본문을 검증하면 1항으로 연결된다. 다음 도식의 E1과 U1은 실제 해시 ID를 줄여 쓴 별칭이다.

그림 1. 같은 조문의 후보 네 개 중 계층과 전체 본문이 일치하는 1항을 선택한다. E1·U1은 실제 ID의 별칭이고 본문은 그림에서만 생략했다.

이 과정을 거치면 질문 → 근거 → 코퍼스의 법령 항목 관계를 ID로 조회할 수 있다. 이 사례에서는 해당 질문의 정답 근거가 법령 항목 U1에 연결된다.

4. 정답표의 구조

앞의 실제 사례는 근거 하나가 법령 한 항목에 연결된다. 검색 평가용 정답표인 qrels에는 여러 항목을 합쳐야 하는 관계도 저장한다. 다음은 별도의 가상 질문 Q2를 사용한 구조 예시다. 실제 사례의 별칭과 구분하기 위해 근거는 E2·E3, 법령은 U2·U3·U4로 표시했다.

{
  "Q2": {
    "E2": ["U2", "U3"],
    "E3": ["U4"]
  }
}

이 가상 질문 Q2에는 근거 E2와 E3가 필요하다. E2는 U2·U3의 전체 본문으로 구성되고 E3는 U4로 구성된다. 따라서 항목 ID뿐 아니라 해당 근거에 필요한 본문까지 정답 기준에 포함된다.

생성한 파일의 필드와 연결 관계는 다음과 같다. JSON·JSONL 데이터를 테이블 형태로 표현했으며, 화살표의 숫자는 연결 개수를 뜻한다.

그림 2. 질문 하나에 여러 근거가 연결되고, 근거 하나는 여러 법령 항목으로 구성될 수 있다. ‘근거와 법령 연결’은 evidence.unit_ids 배열을 펼친 표현이며 별도 저장 파일은 아니다.

각 파일의 저장 내용과 조회 키를 요약하면 다음과 같다.

파일 저장 내용 연결 키
queries.jsonl 질문과 검색 입력, 참고 답변, 평가 가능 상태 query_id
units.jsonl 법령 항목의 본문과 원본 위치 unit_id
evidence.jsonl 원본 근거와 매핑 결과·이유 query_id, evidence_id, unit_ids
qrels.json 평가 가능한 질문의 정답 연결 질문 → 근거 → 법령 ID 목록
splits.jsonl 개발·최종 평가·보류 구분 query_id

매핑 장부에는 연결 결과와 판정 이유를 남겨 추적할 수 있게 했다.

5. 테스트셋 생성 결과와 보류 기준

근거가 하나라도 미해결이면 질문 전체를 보류했다. 일부 근거만 정답으로 남기면 질문이 원래보다 쉬워질 수 있기 때문이다. 마침표 차이나 같은 조문에서 재구성할 수 없는 본문도 임의로 수정하지 않고 실패 이유를 기록했다.

생성 결과 수치
원본 질문 / 근거 주석 226 / 443
단일 법령 항목과 일치 410
여러 항목을 원본 순서로 결합해 일치 24
QA 근거의 등장 순서로 결합해 일치 5
미해결 근거 4
평가 가능 / 보류 질문 222 / 4
qrels에 포함된 근거 연결 434
dev / test / holdout 질문 44 / 178 / 4

qrels의 434건은 전체 근거 443건에서 미해결 4건과 보류 질문에 속한 나머지 근거 5건을 제외한 결과다. 통계와 검증 결과는 audit summary에 기록했다.

개발·설정 조정용 dev, 최종 평가용 test, 미해결 질문 보관용 holdout으로 분할했다. 같은 질문 ID 계열이나 유사한 배경·질문을 가진 항목을 그룹으로 묶어 dev와 test에 걸치지 않게 했다. 다만 두 분할은 같은 법령 코퍼스를 사용하며, 공유하는 정답 근거가 10개 있다. 처음 보는 법령에 대한 일반화 성능을 측정하는 구성은 아니다.

6. 생성 범위와 한계

생성한 결과는 질문, 검색 대상 법령, 정답 근거의 연결, 개발·최종 평가용 분할이다. 검증 대상은 이 데이터의 매핑과 분할이며, 실제 검색이나 답변 생성의 성능은 측정하지 않았다.

이 매핑은 원본에 주석된 근거와 코퍼스 본문이 일치하는지 검증한 결과다. 법령의 적용 시점이나 법률적 정답성을 독립적인 전문가가 검수한 것은 아니다. 원본의 구조화된 시점 정보도 충분하지 않아 추가 검토가 필요하다.

자세한 필드와 연결 구조는 데이터 흐름 문서에 정리했다.
